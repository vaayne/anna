## MCP 服务器的作用

Stella 可以连接外部 [Model Context Protocol](https://modelcontextprotocol.io) 服务器，并把它们的工具暴露给你的智能体。注册一次后，这些工具就会出现在智能体的工具箱中，并以 `mcp__<服务器>__<工具>` 命名，避免与技能或内置工具冲突。

Stella 仅作为基于 HTTP 传输的 MCP **客户端**：

- `streamable_http` — 可流式 HTTP 传输（默认）。
- `sse` — HTTP + Server-Sent Events。

本地 `stdio` 服务器有意不受支持：多用户沙箱绝不会启动本地进程。

端点必须解析到公网地址。回环与私网 URL 会被拒绝，除非运维以 `STELLA_MCP_ALLOW_PRIVATE_ENDPOINTS=1` 启动 `stellad`，该开关面向本地开发服务器。

## 作用域

注册使用与技能和保险库相同的四种作用域，因此服务器可以共享或私有：

| 作用域         | 可见范围                   |
| -------------- | -------------------------- |
| `system`       | 所有智能体、所有用户       |
| `system_agent` | 某个智能体，跨所有用户     |
| `user`         | 某个用户，跨其所有智能体   |
| `user_agent`   | 某个用户搭配某个特定智能体 |

当两个注册同名时，最具体者优先：`user_agent` > `user` > `system_agent` > `system`。

## 认证

服务器可能需要 bearer 令牌。在 Web UI 中创建或编辑 MCP 插件配置时配置它；凭据输入只写入，按配置作用域**加密存储于保险库**（参见[密钥与凭据](/docs/guides/secrets-and-keys)），API 永不返回凭据。无需认证的服务器不需要凭据，即使未配置保险库也可使用。

## OAuth 连接

需要 OAuth 2.1（授权码 + PKCE）的服务器可以在 Web UI 中连接。将认证类型选择为 **OAuth 2.1**，然后在服务器卡片上点击 **连接**。Stella 会自动发现授权服务器，必要时注册客户端，并打开提供商的授权页面；成功后令牌会**加密存储于保险库**，并对服务器执行探测。

- **重定向 URI**：`<STELLA_BASE_URL>/api/mcp/oauth/callback`。基础 URL 必须是浏览器可达的——通过 ingress 或发布端口，而不是仅限集群内部。
- **预注册 vs 动态客户端**：如果提供商要求固定客户端，请在注册表单中填写其**客户端 ID**（以及密钥，如有）。否则 Stella 会在首次连接时动态注册客户端（DCR）并复用。
- **凭据模式**：`system` / `system_agent` 注册可以是 `shared`（所有人共用一个连接）或 `per_user`（每个用户连接自己的账号；未连接的用户看到的工具为 `needs_auth`）。普通用户只能连接其可见的 `per_user` 注册，绝不能连接共享的系统凭据。
- **刷新与重连**：访问令牌会在过期前自动刷新。如果服务器拒绝凭据，服务器会转为 `needs_auth`；点击 **重新连接** 再次授权。**断开连接** 会移除已存储的授权，后续工具调用将失败关闭。

## 状态与探测

Stella 会探测每台已注册的服务器——建立连接并获取其工具列表——并把结果记录在注册上：

| 状态         | 含义                                           |
| ------------ | ---------------------------------------------- |
| `unknown`    | 尚未探测                                       |
| `ok`         | 上次探测成功连接并列出了工具                   |
| `error`      | 上次探测或工具调用失败；界面会显示脱敏后的原因 |
| `needs_auth` | 服务器以 401/403 拒绝了已存储的凭据            |

创建或更新配置不会自动探测服务器。保存后可在 Web UI 中点击 **Probe**，或调用 `POST /api/plugins/{kind}/{name}/configs/{config_id}/probe` 检查连接。智能体会话需要工具目录，而目录尚不存在或上次快照超过 24 小时时，Stella 也会刷新发现结果。探测失败会更新连接状态，并显示脱敏后的原因。

当工具调用被 401/403 拒绝时，服务器会转为 `needs_auth`；在 Web UI 中更新凭据后重新探测即可。

## 工具级权限

服务器暴露的每个工具都可以单独开启或关闭，使用与其它所有工具相同的四作用域覆盖模型：

| 作用域         | 适用于                             |
| -------------- | ---------------------------------- |
| `user_agent`   | 你自己，某个特定智能体（最具体）   |
| `user`         | 你自己，所有智能体                 |
| `system_agent` | 某个智能体，所有用户（仅限管理员） |
| `system`       | 整个部署（仅限管理员）             |

管理员的**禁用**始终优先于用户的启用；否则更具体的用户层优先。在**个人设置 → 智能体 → 工具**（或管理控制台的 system 作用域）中切换工具，或使用 `PATCH /api/agents/{id}/tools/{toolName}`。

服务器的**启用开关是独立的**：它控制整个注册的开关。当服务器被禁用、不可达或凭据被拒绝时，其工具仍会列出，但它们的开关在服务器恢复健康之前不会生效——头部会显示原因。

由于覆盖按工具名（`mcp__<服务器>__<工具>`）作为键，重命名服务器会自动把其工具的覆盖迁移到新前缀，删除服务器则会移除它们；两者都只在任何作用域里都没有其他注册使用该名称时才会发生。如果两个不同作用域的注册同名，覆盖作用于当前上下文中胜出的那个注册。

## 市场

无需手动输入 URL，可以在**市场**标签页浏览：它列出官方 [MCP Registry](https://registry.modelcontextprotocol.io) 中带可流式 HTTP 端点的远程服务器，并显示每条的认证方式：

- **无需认证** — 安装即用。
- **Bearer** — 安装后按条目头部模板粘贴所需的 API 密钥。
- **需要手动配置**（`unsupported`）—— 条目需要市场无法替你填写的自定义头部；仍可在 Manual 标签中先在带外配置好再安装。
- **OAuth** — 未声明认证的条目仍可能需要 OAuth；安装后的首次探测会识别这一点，服务器显示*需要认证*并提供连接按钮。

安装时会把注册表来源、ID 和版本写入注册记录，便于后续核对。同一作用域下安装重复的 URL 会返回已存在的注册，而不是创建副本。

注册表来源可通过环境变量 `STELLA_MCP_REGISTRY_URL` 覆盖（例如镜像站）；默认为官方注册表。

## 管理服务器

在 **个人设置 → 插件** 管理个人的 `user` 与 `user_agent` 配置。管理员在 **管理控制台 → 集成 → 插件** 管理部署所有的 `system` 与 `system_agent` 配置。添加 MCP 插件配置，选择适用于全部智能体或单个智能体；如果服务器需要认证，再提供凭据。MCP 没有独立的管理 API：管理通过 Web UI 和 `/api/plugins` 下的统一插件 API 进行，智能体仍可使用 `settings_mcp_server_*` 工具执行面向模型的管理操作。

## 故障排除

| 现象                       | 含义                                         | 处理                                                          |
| -------------------------- | -------------------------------------------- | ------------------------------------------------------------- |
| 服务器显示**需要认证**     | 已存储的凭据（或 OAuth 授权）被 401/403 拒绝 | OAuth 服务器请重新连接；bearer 服务器请更新令牌，然后重新探测 |
| 服务器显示**错误**         | 上次探测时端点不可达                         | 确认 URL 可从服务端访问后重新探测                             |
| 工具开关不生效             | 服务器被禁用或状态异常                       | 先恢复服务器状态；头部会说明原因                              |
| 市场中显示**需要手动配置** | 条目需要自定义请求头                         | 先在带外配置好头部，再从 Manual 标签添加                      |
| OAuth 回调无法返回         | `STELLA_BASE_URL` 浏览器不可达               | 让基础 URL 可达（ingress、发布端口）后重新连接                |
| 服务器新增工具后工具缺失   | 持久化目录早于变更                           | 探测服务器——或等待：`tools/list_changed` 会触发后台刷新       |
